# Machine-readable finite data

These deterministic JSON exports are provided for convenient reuse. The copied
appendix data sources and original `verification/` modules are the authoritative
inputs; the exports are generated by `scripts/export_data.py` using exact
integer and rational arithmetic.

| File | Contents | Paper location |
| --- | --- | --- |
| [simple-example.json](simple-example.json) | `U8`, its complement, `F9`, `K9`, and the 128-word OR-square code | Section 2, `sec:simple` |
| [subsix.json](subsix.json) | The 54-by-27 construction: graphs `B,D,G,H`, two 27-word OR-square codes, ternary source vectors, fitting matrices, three complete integer Gram matrices, orbit entries, and exact bounds | Appendix F, `sec:subsixproof` |
| [thresholds.json](thresholds.json) | Primitive graphs `U6`, its complement, `R`, `C5`, `Z`, and `Q`; the 37-, 5-, 81-, and 16-word codes; the eight-row coverage table; exact cutoff parameters | Appendix G, `sec:thresholdproof` |

From the repository root, run:

```sh
python3 scripts/export_data.py          # regenerate the three JSON files
python3 scripts/export_data.py --check  # compare without changing them
```

Python 3.11 or later is required; there are no third-party dependencies. The
exporter refuses optimized Python execution because original verifiers use
assertions. Do not use `-O`, `-OO`, or set `PYTHONOPTIMIZE`.

## Conventions

- Every graph is simple and undirected. `vertex_labels[i]` identifies row and
  column `i`; character `j` in `adjacency_rows[i]` is its zero/one adjacency.
- All codewords use **zero-based row indices**, including the graph `H`, whose
  native residue labels skip 1 and 17. Map a code symbol `i` back to its label
  with `vertex_labels[i]`. Every exported code is checked pairwise for OR
  adjacency during export.
- In the sub-six graph `G`, vertices 0 through 26 are the `B` component and 27
  through 53 are the `D` component in the same ternary-vector order.
- Integer Gram matrices have diagonal `diagonal` and entry `-scale` on graph
  edges. The rational certificate is the displayed integer matrix divided by
  `scale`; its capacity upper bound is `1 + diagonal/scale`.
- Entries of fitting matrices are representatives 0, 1, 2 in `F3`. The `H`
  fitting matrix has two consecutive rows/columns per vertex; within each
  pair the zero-based colour indices increase.
- Exact noninteger rational values are strings such as `13/1000`, never
  floating-point JSON numbers. Symbolic quantities such as `sqrt(27)` remain
  strings. Large integer matrix entries remain JSON integers; software with
  limited integer precision must parse them accordingly.
- Matrix SHA-256 values hash the ASCII bytes of the matrix as a compact JSON
  array of integer rows, with separators `,` and `:` and no trailing newline.
  They do not hash the pretty-printed dataset files.
- Coverage-table graph expressions retain the manuscript's LaTeX notation.
  For example, `3C_5` denotes the **join** of three pentagons.

## Scope

The exporter first runs the modular sub-six checks and the finite Appendix G
checks, compares the printed `H` adjacency with the embedded data, and checks
the Gram-matrix hashes against the modular verifier's report. The independent
source-derived auditors remain separate programs in `verification/`; run the
full verification suite to check the manuscript tables independently.

The Section 2 export is newly generated directly from the graph definition and
checks its finite 128-word code. It does not computer-prove the analytical
capacity upper bound. General graph families, joins used to pad every real
threshold, asymptotic constructions, and analytical identities are specified
by the accompanying manuscript and are not exhaustively instantiated in JSON. The full manuscript is not included in this code/data repository.
Historical search candidates and superseded 54-by-28 datasets are not part of
these exports. Re-exporting data does not discover or optimize certificates.
